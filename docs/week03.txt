第3週 正規表現 → NFA → DFA
================================
日付: 2026-11-10(第3週)

■ ステップ1:正規表現の基本

【なぜ正規表現か】
・9cc の tokenize は if で手書き。変数名・キーワード・== などが増えると漏れやすい
・流れ:正規表現でトークンを書く → オートマトンに変換 → プログラムにする
・これを自動でやるのが flex(第4週)。今週は中で起きていることを手で追う

【用語】
・アルファベット Σ:使ってよい文字の集まり(例 {a, b})
・空文字列 ε:長さ0の文字列
・言語:文字列の集合。正規表現は言語を短く書く書き方

【3つの基本操作】
・連結 ab:a の後に b
・選択 a|b:a か b
・繰り返し a*:a を0回以上(ε も含む)
・優先順位:* > 連結 > |
    ab* = a(b*)、ab|c = (ab)|c。変えたいときは ( )

【省略形】
・a+ = aa*(1回以上)
・a? = a|ε(0回か1回)
・[0-9] = 0|1|…|9

【例】
・整数:[0-9]+
・変数名:[a-zA-Z_][a-zA-Z0-9_]*
・0と1だけで、1で始まる文字列:1(0|1)*
・a(b|c)* に当てはまる:a, abcb, acc / 当てはまらない:bc(a で始まらない)
・(a|b)*abb:a と b からなり、abb で終わる文字列(今週ずっと使う例)

■ ステップ2:DFA(決定性有限オートマトン)

【DFAとは】
・文字を1つずつ読んで状態を移る機械。最後に受理状態にいれば受理
・部品:状態 ○ / 開始状態 →○(1つだけ)/ 受理状態 ◎ / 遷移(矢印に文字)
・決定性:どの状態でどの文字を読んでも、次の状態がちょうど1つに決まる

【例1:[0-9]+】
・S0(開始)→数字→ S1(受理)→数字→ S1
・"42" 受理 / "" 拒否(S0は受理状態でない)/ "4a" 拒否

【死に状態】
・遷移が書いていない文字が来たら、二度と受理に戻れない状態に行く
・図では省略する。矢印がない = 拒否
・例:1(0|1)* の DFA
            0   1
    S0(開始) D   S1
    S1(受理) S1  S1
    D(死に)  D   D

【例2:(a|b)*abb】
・状態 0,1,2,3(3が受理)。各状態は「abb のどこまで一致しているか」
        a  b
    0 → 1  0
    1 → 1  2
    2 → 1  3
    3 → 1  0
・babb:0→0→1→2→3 受理 / aabb:0→1→1→2→3 受理 / abab:0→1→2→1→2 拒否
・aba の最後の a は新しい abb の始まりかもしれないので、0 ではなく 1 に戻る

【DFAはプログラムになる】
    //                a  b
    int table[4][2] = {{1, 0}, {1, 2}, {1, 3}, {1, 0}};
    int state = 0;
    for (char *p = input; *p; p++)
      state = table[state][*p - 'a'];
    bool accept = (state == 3);
・表を2次元配列にして、1文字ずつ state = table[state][文字] とするだけ
・1文字につき表を1回引くだけなので速い
・flex が出力するCコードも、この表とループの形

【補足:for の真ん中の *p】
・for は for (最初にやること; 続ける条件; 毎回の最後にやること) という形
  真ん中の *p は「続ける条件」
・*p は、p が指している1文字
・Cの文字列は、最後に '\0'(ヌル文字。値は0)が必ず付いている
・Cでは 0 は偽、0以外は真
・なので「*p が '\0' でない間(=文字列の終わりに来るまで)続ける」という意味
  *p != '\0' を短く書いたもの
・"ab" で追うと
    p が指す文字   *p の値   続けるか
    'a'            97        真 → 続ける
    'b'            98        真 → 続ける
    '\0'           0         偽 → 終わる
・9cc の tokenize の while (*p) も同じ意味

■ ステップ3:NFA(非決定性有限オートマトン)と ε遷移

【DFAとの違い】
・同じ状態・同じ文字でも、行き先が複数(または0個)あってよい
・文字を読まずに移る ε遷移があってよい

【受理の決まり】
・どれか1本でも受理状態にたどり着く道があれば受理
・分かれ道のたびに分身して、全部の道を同時に進むと考える

【(a|b)*abb の NFA】
         a      b
    0 → {0,1}  {0}
    1 →  −     {2}
    2 →  −     {3}
    3(受理)
・0 で a を読むと「0に残る」と「1に進む」の2通り = abb の始まりかを推測している

【動かし方:今いる状態の集合を追う】
・babb:{0}→{0}→{0,1}→{0,2}→{0,3} 受理
・abab:{0}→{0,1}→{0,2}→{0,1}→{0,2} 拒否
・aab :{0}→{0,1}→{0,1}→{0,2} 拒否
・NFA の集合 {0},{0,1},{0,2},{0,3} が DFA の状態 0,1,2,3 にぴったり対応
  → 集合1つを DFA の状態1つとみなすのが部分集合構成法(ステップ5)

【ε遷移とε閉包】
・ε遷移:文字を読まずに移ってよい矢印
・ε閉包:ある集合から ε遷移だけでたどり着ける状態を全部足したもの
・1文字読むたびに ε閉包を取る(最初の状態にも取る)
・例:a|b の NFA(0─ε→1─a→2─ε→5、0─ε→3─b→4─ε→5、5が受理)
    最初:ε閉包({0}) = {0,1,3}
    a を読む:{2} → ε閉包 {2,5} 受理
    b を読む:{4} → ε閉包 {4,5} 受理

【なぜ NFA を使うか】
・NFA:正規表現から機械的に作れる / 動かすのは遅い(毎回、集合を計算する)
・DFA:直接作るのは難しい / 表を1回引くだけで速い
・正規表現 → NFA → DFA → プログラム
・NFA と DFA が表せる言語の範囲は同じ

■ ステップ4:正規表現 → NFA(トンプソンの構成法)

【考え方】
・どんな正規表現からでも、決まった手順だけで NFA を作る(flex にやらせられる)
・「1文字」と「連結・選択・繰り返し」の4つの決まりで組み立てる
・どの部品も入口1つ・出口1つにする → つなぐのが簡単

【4つの決まり】
・1文字 a:i ─a→ f
・連結 st:s の出口 ─ε→ t の入口(まとめて1つの状態にしてもよい)
・選択 s|t:新しい i と f。i ─ε→ s と t の入口、s と t の出口 ─ε→ f
・繰り返し s*:新しい i と f。ε を4本
    i → s の入口(1回目)/ s の出口 → s の入口(もう1回)
    s の出口 → f(終わる)/ i → f(0回。忘れやすい)
・選択 | と繰り返し * は、どちらも新しい状態を2個足す

【例:a* の NFA(4状態)】
・a だけで2個(1 ─a→ 2)、* で新しい入口 0 と出口 3 を足して +2個
    状態     ε      a
    0(開始)  1, 3          0→1:1回目 / 0→3:0回で終わる
    1               2      a の部品の入口
    2        1, 3          2→1:もう1回 / 2→3:終わる
    3(受理)
・"" → ε閉包({0}) = {0,1,3} 受理(0→3 の ε があるから)
・a  → {2} → ε閉包 {1,2,3} 受理

【(a|b)*abb を組み立てる】
・(1) a:2─a→3、b:4─b→5
・(2) a|b:1─ε→2, 1─ε→4, 3─ε→6, 5─ε→6
・(3) (a|b)*:0─ε→1, 6─ε→1, 6─ε→7, 0─ε→7
・(4) abb:7─a→8─b→9─b→10
・完成:状態 0〜10 の11個、開始0、受理10
    状態  ε     a   b
    0     1,7
    1     2,4
    2           3
    3     6
    4               5
    5     6
    6     1,7
    7           8
    8               9
    9               10
    10(受理)
・手で描いた NFA(4状態)より大きいが、考えずに作れることが大事

■ ステップ5:NFA → DFA(部分集合構成法)

【考え方】
・NFA を動かすときの「今いる状態の集合」1つを、DFA の状態1つとみなす

【2つの道具】
・move(T, x):集合 T の各状態から、文字 x の矢印で1歩進んだ先を全部集めたもの
・ε閉包(U):U から ε の矢印だけで行ける状態を全部足したもの
・1文字読んだあとの集合 = ε閉包(move(T, x))(1歩進んで、ε で広げる)

【手順】
1. 開始状態:ε閉包({0}) を A とする
2. まだ調べていない集合 T を選び、a と b それぞれで U = ε閉包(move(T, x))
   新しい集合なら名前を付け、表に T ─x→ U と書く
3. 調べていない集合がなくなるまでくり返す
4. NFA の受理状態(10)を含む集合が、DFA の受理状態

【注意:矢印のない状態は消える】
・move は「文字を読んで進んだ先だけ」を集める。前にいた状態は残さない
・例:B を b で読むとき、b の矢印があるのは 4 と 8 だけ。1,2,3,6,7 は消える
・コツ:ε閉包は、新しい状態が増えなくなるまで ε の矢印をたどる

【手計算(ステップ4の11状態 NFA から)】
・A = ε閉包({0}) = {0,1,2,4,7}
・A を a:move = {3,8}(2→3, 7→8)
         ε閉包 = {1,2,3,4,6,7,8} → B(新)
・A を b:move = {5}(4→5)
         ε閉包 = {1,2,4,5,6,7} → C(新)
・B を a:move = {3,8} → B
・B を b:move = {5,9}(4→5, 8→9)
         ε閉包 = {1,2,4,5,6,7,9} → D(新)
・C を a:move = {3,8} → B
・C を b:move = {5}(4→5)→ C
・D を a:move = {3,8} → B
・D を b:move = {5,10}(4→5, 9→10)
         ε閉包 = {1,2,4,5,6,7,10} → E(新)
・E を a:move = {3,8} → B
・E を b:move = {5}(4→5)→ C
・新しい集合が出なくなったので終わり
・どの集合も 2 と 7 を含むので、a を読むと必ず {3,8} → B になる

【完成した DFA】
    DFA        NFA の集合               a  b
    A(開始)   {0,1,2,4,7}              B  C
    B          {1,2,3,4,6,7,8}          B  D
    C          {1,2,4,5,6,7}            B  C
    D          {1,2,4,5,6,7,9}          B  E
    E(受理)   {1,2,4,5,6,7,10}         B  C
・受理状態は 10 を含む E だけ
・11状態の NFA → 5状態の DFA

【ステップ2の DFA との比較:最小化】
・A と C の行がまったく同じ(a で B、b で C)→ 1つにまとめられる
・まとめると A,C→0、B→1、D→2、E→3 で、ステップ2の DFA と一致
・同じ動きの状態をまとめて小さくすること = DFA の最小化(flex も最後にやる)
・(a|b)*abb → NFA 11状態 → DFA 5状態 → 最小化 4状態

■ ステップ6:9cc の tokenize との対応

【全部のトークンを1つの DFA に】
・トークンの正規表現を | でつないで1つの DFA にする
・受理状態に「何のトークンか」の名前を付ける

【決まり1:最長一致】
・受理状態に入っても止まらず、進める限り読む。最後に通った受理状態をトークンにする
・<= → [<=] の1つ([<][=] にはしない)
・規則 < <= = == で "<==" → [<=][=]
・9cc の strtol も最長一致(123+ で 123 まで読む)

【決まり2:同じ長さなら先に書いた規則が勝つ】
・if はキーワードにも変数名 [a-z]+ にも当てはまる → キーワードを先に書く
・優先は最長一致のほう。長さが違えば、書いた順番に関係なく長いほう
・"iffy" → [iffy] で変数名1つ(キーワード if は2文字分しか当てはまらない)
